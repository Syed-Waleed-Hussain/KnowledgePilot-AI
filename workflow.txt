3. Student ka end-to-end workflow

1. Student registration

Student signup/login karega. System uske liye unique user ID aur private workspace create karega.



2. Create course

For example: Information Security, Artificial Intelligence, PDC. Har course ki unique ID hogi.



3. Upload documents

PDF, DOCX, PPTX, TXT. Files private storage mein save hongi aur background indexing job start hogi.



4. Processing

Text extraction, cleaning, chunking, embeddings aur vector indexing. UI mein Processing → Ready ya Failed status dikhega.



5. Ask AI

Student selected course se question poochega. Retrieval sirf authorized documents se hogi.



6. Agent execution

Agent task classify karega, tool choose karega, relevant information fetch karega aur answer banayega.



7. Verification + feedback

Citation validation, final response, student rating aur evaluation logging.



Example: Student ne 2:00 PM par lecture upload ki. Upload process complete hote hi, bina server restart ya manually training kiye woh us lecture se questions pooch sakega. Actual processing time file aur server par depend karega.
4. Development modules — kya kya build hoga?
Module A — User accounts and course management
Ismein hum student account system banayenge.

Features: signup, login, logout, student dashboard, create/rename/delete course, upload and manage notes, chat history, delete account and personal data.

Backend design: users, courses, documents, chats, messages jaisi relational tables. Har owned resource ki user ID backend par verify hogi.

Security: sirf frontend par course hide karna sufficient nahi. Backend query aur vector search dono ko user permissions enforce karni hongi.

Output: do alag accounts simultaneously login karke apna data independently access kar saken.

Module C — RAG engine
Yeh agent ka knowledge-retrieval system hai.

Example:

Student: "Explain SQL Injection from Week 8."

RAG engine:
1. Student ka authorized course identify karega.
2. Question ka embedding generate karega.
3. Relevant chunks vector database se retrieve karega.
4. Chunks aur source metadata LLM ko provide karega.
5. Answer ke saath actual document/page references return karega.
Hum hybrid retrieval aur reranking ko later improvements mein consider karenge, agar initial semantic retrieval insufficient ho.

Important: Agar information documents mein na ho, agent ko clearly bolna hoga ke provided material mein answer nahi mila. Invented citations allowed nahi hongi.

Module F — Agent Harness
Agent harness hamare agent ki execution ko reliable aur controlled banayega.
Harness subsystem	Hamara implementation
Context management	Relevant context selection, token limits
Tool execution	Tool schemas, permissions, allowed calls
State and memory	Chat state, checkpoints, user-scoped memory
Error recovery	Timeouts, safe retries, failure handling
Verification	Evidence-based answer checks
Observability	Execution logs, traces, latency and token usage

Practical example: Agar Research API fail ho jaye, harness configured retry karega. Agar phir bhi unavailable ho, agent fabricated paper results dene ke bajaye error explain karega.

Memory mein bhi distinction rakhenge: short-term conversation state, saved course knowledge aur explicitly permitted long-term preferences alag honge.
Module G — Reinforcement Learning
Bhai, yeh advanced module hamara differentiator ho sakta hai — lekin isko scientifically defensible tarike se implement karenge.

RL ka goal: agent ko better tool/retrieval strategy select karna sikhana.

Initial version mein contextual bandit use karenge.
Illustrative RL Experiment
ContextStudent asks a complex question about two lectures.


Available strategies
A. Retrieve top 3 chunks
Action A

B. Retrieve top 8 chunks
Action B

C. Multi-query retrieval
Action C



Evaluate result
Correctness • Citation grounding • Latency • Cost

Reward → Update Policy
Learn which strategy performs best for similar contexts

For example, experiment ke liye reward define kar sakte hain:
\[
R=0.5A+0.3C+0.2E
\]

Where:
- \(A\) = normalized answer accuracy
- \(C\) = verified citation correctness
- \(E\) = normalized efficiency score (latency aur resource usage)
Yeh proposed formula hai, final validated reward function nahi.

RL training workflow: Baseline test → logged actions → evaluated rewards → policy update → held-out testing → compare improvements → approve deployment.

RL ko arbitrary student feedback se immediately model weights modify karne ki permission nahi denge. Feedback noisy ho sakta hai; privacy aur reward hacking dono handle karna hoga.

Future extension mein PPO/GRPO jaisi LLM fine-tuning techniques explore kar sakte hain, lekin unhein MVP ka compulsory requirement nahi banayenge.
Module H — Research Assistant
Student apna FYP topic enter karega. Research module:
- arXiv / Semantic Scholar APIs se relevant papers search karega.
- Title, authors, year, URL/DOI aur abstract display karega.
- Selected accessible papers ko knowledge base mein index karega.
- Methodology, findings, limitations aur research gap compare karega.
- Source-backed literature review draft create karega.
- Paper metadata aur generated review mein verified references rakhega.
Agar full paper accessible nahi hai to assistant explicitly batayega ke analysis abstract-based hai.
Module I — Automation and deadlines
Student course deadlines manually enter karega ya available structured documents se suggested dates extract karwa sakega.

n8n ke through reminders automate kar sakte hain, initially in-app/email workflow ke saath.

Deadline extract hone par automatic scheduling ke bajaye user confirmation lenge, kyunki PDF date interpretation incorrect ho sakti hai.
Module J — Evaluation and testing
Sir ko demonstrate karna hai ke system accurate aur useful hai.

Hum ek evaluation dataset create karenge, jisme manually verified questions, answers aur document citations hon.
Metric	Kya measure hoga?
Retrieval Recall@K	Correct evidence retrieve hua?
Citation accuracy	Citation actual source support karti hai?
Answer correctness	Answer factually correct hai?
Faithfulness	Answer provided evidence se supported hai?
ROUGE / BLEU	Reference summary se text overlap
Tool success rate	Agent correct tools execute karta hai?
Task completion	Multi-step request complete hui?
Latency	Response kitni quickly aaya?
User isolation	Cross-user access blocked hai?
RL improvement	Learned policy baseline se better hai?

ROUGE/BLEU ko retain karenge kyunki proposal mein hai, lekin unko factual correctness ka sole measure nahi banayenge.

8. How we'll make the project viva-proof
Tumhare sir ne coding independently karne ki instruction di hai, isliye har phase mein hamara learning pattern hoga:

Concept → Diagram → Small coding exercise → Your implementation → Debugging → Testing → Viva.

For example, RAG module ke waqt tumhe yeh samajhna hoga:
- Embeddings kya hain aur keyword search se kaise different hain?
- Chunk size aur overlap kyun important hain?
- Similarity search kaise work karti hai?
- RAG aur fine-tuning mein difference kya hai?
- Citation kaise verify karte hain?
- User A ka data User B ko kyun nahi milna chahiye?
- Agent harness aur LangGraph mein difference kya hai?
- RL policy ne improvement ki ya nahi, kaise prove karoge?
Sir agar code mein retrieval count 5 se 10 karne ko bol dein, tumhe uska impact explain karna aana chahiye.
